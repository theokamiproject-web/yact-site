# Gmail下書き運用の勘所

Gmail MCPで下書きを作るときに繰り返しつまずく点と、その回避策。

## 1. URLが `www.google.com/url?q=...` に化ける

**症状**：`body`（プレーンテキスト）に素のURLを書くと、Gmailが自動リンク化するときに転送用ラッパーを付ける。下書きを開くと表示テキスト自体が長い転送URLになり、見苦しい。

**回避**：`htmlBody` を使い、表示テキストを明示的に指定する。

```html
<div style="white-space:pre-wrap;font-family:sans-serif;font-size:14px">
本文…
<a href="https://maps.app.goo.gl/XXXX">https://maps.app.goo.gl/XXXX</a>
</div>
```

`white-space:pre-wrap` を付ければ改行がそのまま活きるので、プレーンテキストと同じ書き味で組める。hrefが書き換えられても**表示は指定したまま**残る。

**ユーザーが手で貼る場合**：貼り付け直後に `Ctrl+Z` を1回押すと自動リンク化だけが取り消される。または貼付後に該当箇所を選び「リンクを削除」。

## 2. 下書きが消える

Gmail MCPで作った下書きは、**予告なく消えることがある**（同期の問題か、ユーザーが誤って破棄したか）。実際に1セッション中で3回消えた。

- **重要な文面は必ずGoogleドキュメントにも残す。** 宛先（BCCのアドレス一覧）も一緒に。復元が一瞬で済む。
- `update_draft` が `AppErrorCode=5` を返したら、その下書きは既に存在しない。`list_drafts` で確認し、`create_draft` で作り直す。
- **作り直す前に、送信済み（`in:sent`）を検索する。** ユーザーが自分で送ったために下書きが消えていた実例がある。送信済みに入っていれば作り直さない。
- 生成スクリプトや文面テンプレートは outputs に置く。`/tmp` は消える。

## 3. BCC一斉送信

- `to` は自分のアドレス、`bcc` に受信者全員。
- **送信前にTO/BCCを必ず目視確認する。** BCCがTOに入ると全員のアドレスが露出する。事故は取り返しがつかない。
- 相手の状況で文面が変わる場合は、無理に1通にまとめず**グループごとに分ける**。宛先リストはドキュメントに残しておく。
- 同じ人が複数グループに該当する場合（例：両方の回に来場）は、意図的に両方へ入れるのか、片方に絞るのかを決めて注記する。

## 4. 返信として送る

`replyToMessageId` に元メッセージのIDを渡すとスレッドに紐づく。IDは `search_threads` → `get_thread` で取得。

ただし、**ユーザーが受信トレイから直接返信したい**場合も多い。そのときは下書きを作らず、本文をチャットにコピペできる形で出す。

## 5. 送信

環境によって、送信ツール（`send_message`）がある場合とない場合がある。ToolSearch で確かめる。

**送信ツールがない場合**：`create_draft` / `update_draft` のみ。**下書きまでが自分の仕事**。「送っておいて」と言われたら、下書きを整えたうえで、送信はGmailで行っていただく旨を伝える。

**送信ツールがある場合**：
- 既定は下書きまで。**送るのは、ユーザーが下書きを見て「送って」「送っておｋ」と明示したときだけ。** 1件ずつOKの範囲を確かめる（「この2人だけ」など）。
- 下書きの `draftId` を指定して送る（本文を作り直さない）。
- 送ったら `in:sent` で送信済みに入ったことを確かめてから「送りました」と報告する。
- 送信が安全確認で止められたら、**別の方法で送り直さない。** 下書きは残っているので、Gmailから手で送ってもらうよう伝える（10通中1通が止められた実例）。

## 6. CC・宛先を外したいとき

CCだけを外す手段がなかったので、**新しい下書きを正しい宛先で作り直し、古い下書きを削除した。** 作り直した下書きに本文・件名がすべて入っているか確かめてから古いほうを消す。
- 本文に外した人への言及（「○○様にもCCでお送りしています」など）があれば、それも消す。
