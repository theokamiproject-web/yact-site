# tshirt-order-handoff

## Purpose
決まったTシャツデザインを、印刷会社が**そのまま製版に進める形**で渡し、納期と再入稿のリスクを先に潰す。

## When to use / NOT
- 使う: デザイン確定後の入稿・見積・納期確認・追加会社の探索・枚数集計。
- 使わない: デザイン案づくり／紙物の表紙・チラシ（→ `print-cover-pdf`）。

## 版データの定義（取り違え防止。READMEとメールに必ず書く）
- **版（plate.png/svg）は「黒＝インクが乗る場所、白＝抜き」**。生地の色ではない。
- 濃色生地では**下地に白インク**を引く。下地版は本版と同形（縮小=チョークは会社の指示）。版が黒で描かれていても「下地も黒インク」ではない。
- `feature_check.py` は「黒=インク」前提。入力が反転(黒地ベタ・インク面積が過大)に見える場合は exit 2 で止まる。

## Inputs
確定デザインのSVG（mm寸法・位置）、生地色、位置、枚数×サイズ、希望納着日、依頼主連絡先。**印刷会社の最新ルール**（WebFetchで取得。`references/vendor-rules.md` は観測例にすぎない）。会社名・住所・電話は【】で空欄のまま渡す（作らない）。

## Workflow
0. 環境: `node`+`playwright(-core)`+Chromium、python `numpy pillow scipy`、`pdfimages`。足りなければ各スクリプトが exit 3 で止まる。**止まったら成功扱いにせず**不足を報告。
1. **確定条件を表に固定**（生地色・位置・寸法・色数・枚数×サイズ・納期）。位置は「着用者から見て」と明記。
2. **会社の入稿ルールを取得**（WebFetch）。形式、アウトライン化、最小線幅/隙間、下地、特急条件・締切。**その時点の値**を以降の引数に使う。
3. **版を作る**: `make_plate.py art.svg plate.svg`（ラスター/`<text>`/stroke/複数インクは拒否される）。
4. **一式を生成**: `build_handoff.py --plate plate.svg --out DIR --order order.json --min-line <会社値> --min-gap <会社値> [--artwork art.svg]`。内部で ①ラスター検査 ②版→PNG(12px/mm以上) ③最小線幅/隙間検査 を行い、通った場合だけ README・`mail-draft.md`・`report.json` を出力する。
5. **メール**: `templates/mail-inquiry.md.tmpl`（問い合わせ）／`templates/mail-order-followup.md.tmpl`（注文後）。【】以外に作り事を入れない。
6. **納期リスク**: 今日から納着日までの営業日を数え、校正往復・特急条件を足す。足りなければ複数社同時問い合わせを勧める。
7. **枚数集計**: `tally_qty.py rows.csv [--base N --relation add|include]`。
8. **回帰テスト**: スクリプト変更時は `bash .claude/skills/tshirt-order-handoff/tests/run-fixture-test.sh`。

## Decision rules
- `feature_check` が reject(1) → `build_handoff` は一式を作らず止まる。提示する選択肢: ①細部だけ別方式(DTF等) ②簡略化の作り直し ③会社のデータチェックを先に受ける ④**ユーザーが明示的に了承した場合のみ**現状入稿（`--accept-risk "了承文言"`。READMEとメールに「細部の再現なし了承」を記録）。ユーザーが④を選んだら再調整しない。
- **補正は1回まで**。1回で崩れたら自動補正を続けず、上の選択肢へ判断を戻す。細いロゴを自動で太らせ続けない。
- 要確認(2)（中間調・反転疑い・要確認帯）→ 画像を目視して、版の定義(黒=インク)と二値性を確認してから進める。
- **ラスター混在(raster_check=2)** → 既存・他Skillの細線チェッカー(tee-check等)の**PASSは無効**。完成画像を会社値で実測し、確認したら `--raster-reviewed`。
- 拡大で救えるか → 配置上限と拡大率を**その案件の数値で計算**。小さな拡大(約1割)では基準に届かないことが多く、期待させない。
- 会社仕様 ≠ 社内目安 → **会社仕様を優先**。社内目安（`--warn/--reject` の既定 3/10%）は会社が基準を示さない場合の暫定値と明記。
- 納着までの営業日 < 校正+製造の目安 → 特急可否を最優先で聞く／他社へ並行打診。
- 形式が未記載(SVG等) → PDFで渡す（ユーザーが確定したらPDFのみ）。
- 枚数: すでに合計がある場合、新しい人数分が**追加**か**内包(内数)**かを必ず確認してから `--relation` を指定する（未指定はエラー）。
- 文字(OCR・手書き・スクショ)の読みが不確か（Lが「し」に見える等）→ `confidence=uncertain` にして「推定」と明記し、確認を求める。確定扱いで集計しない。

## Quality checks
版: 黒=インク/白=抜き・二値・反転なし／ラスターなし(または実測済み)／会社値で最小線幅・隙間を測定／READMEに下地=白インク・版は黒表記と明記／メールの【】以外に作り事なし／枚数内訳=合計(追加/内包を区別)／納期リスクを日数で提示／リスクとメリットを併記／**環境不足で検査できなかった項目は「未検査」と書く**。

## Failure modes → Recovery
- 版を黒で描いたのを「下地も黒インク」と誤解される → README/メールの定義文。
- 自動で細部を太らせてロゴが潰れる → 1回で止める。
- 位置の左右取り違え → 「着用者から見て」で統一。
- チェッカーPASSでも実物が崩れる → ラスター混在・小さな縮小を疑い、完成画像を実測。
- 環境不足 → 不足を列挙して止まる（成功扱いにしない）。
詳細: `references/vendor-rules.md`（観測例・要再確認）、`references/logo-adaptation.md`。
