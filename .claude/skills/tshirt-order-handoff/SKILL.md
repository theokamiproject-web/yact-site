# tshirt-order-handoff

## Purpose
決まったTシャツデザインを、印刷会社が**そのまま製版に進める形**で渡し、納期と再入稿のリスクを先に潰す。

## When to use / NOT
- 使う: デザイン確定後の入稿・見積・納期確認・追加会社の探索・枚数集計。
- 使わない: デザイン案づくり（デザイン生成用の別Skill）／表紙などの紙物（→ `print-cover-pdf`）。既存の他Skill・検査ツールは**変更しない**。

## Inputs
確定デザインのSVG（mm寸法・位置）、生地色、位置(左胸/背中中央等)、枚数×サイズ、希望納着日、依頼主連絡先。会社の入稿ルール（WebFetch で最新ページを読む。`references/vendor-rules.md` は観測例）。

## Workflow
1. **確定条件を表に固定**（生地色・位置・寸法・色数・枚数×サイズ・納期）。位置は「着用者から見て左」と明記（図は正面から見て右側に出る）。
2. **会社の入稿ルールを取得**（WebFetch）。形式(ai/PDF)、アウトライン化、最小線幅/隙間、下地の扱い、特急条件・締切。
3. **版ごとに数値検査**: `scripts/svg2png.cjs` で版をPNG化（12px/mm以上）→ `scripts/feature_check.py`。社内の暫定基準（検査ツールがあれば）は**会社のルールより緩いことがある**ので、必ず会社値で測る。
4. **不適合の扱い**（decision rules）。
5. **データ一式**: 位置ごとのベクターPDF（文字曲線化）／版PDF・SVG（`make_plate.py`、黒=インク）／`preview-front-back.png`／README（寸法・色・下地・チョーク未設定・「再現性なし了承」等の依頼）。
6. **メール**: `references/mail-templates.md`（問い合わせ／注文後の入稿）。**会社名・住所・電話は空欄【】で渡す**（作らない）。
7. **納期リスク**: 今日から納着日までの営業日を数える。校正往復・特急条件を足して、足りなければ複数社同時問い合わせを勧める。
8. **枚数集計**: スクショ/コメントから人別に表化→サイズ別合計。曖昧な字（Lが「し」に見える等）は推定を明記し確認を求める。元の枚数と**加算か内包か**を必ず確認。

## Decision rules
- 会社ルール不適合(`feature_check` 10%以上) → 提示: ①細部だけ別方式(DTF)／②簡略化の作り直し／③先にデータチェックを受ける／④**ユーザーが了承すれば現状で入稿**（READMEとメールに「細部の再現なし了承」を明記）。ユーザーが④を選んだら再調整しない。
- サイズ拡大で救えるか → 配置上限(例100mm)で拡大率を計算。**約10%程度の拡大では基準(1mm/2mm)に届かない**ので期待させない。
- 画像(ラスター)混在の版 → 社内検査ツールがラスターを対象外にする場合あり（PASSでも無意味）。必ず別途測る。
- 納着まで営業日 < 校正+製造の目安 → 特急可否を最優先で聞く／他社へ並行打診。
- 形式が未記載(SVG等) → PDFで渡す（ユーザーが確定したらPDFのみ）。

## Quality checks
PDFに画像・フォントが無い／寸法=実寸／下地=白インクと明記（版は黒表記）／メールの【】以外に作り事なし／枚数の内訳が合計と一致／納期リスクを日数で提示／リスクとメリットを併記。

## Failure modes → Recovery
- 版を黒で描いたのを「下地も黒インク」と誤解される → READMEとメールに「版は黒=インク表記。下地は白インク」。
- 自動で細部を太らせてロゴが潰れる → 1回試して崩れたら止め、選択肢を提示（無理な自動化を続けない）。
- 位置の左右取り違え → 「着用者から見て」で統一。
