# 公演LPの更新とNetlify公開

## Purpose
LPを壊さずに書き換え、ユーザーの「公開OK」を受けてから本番に出し、出たことを確かめる。

## When to use
- LPの文言・ボタン・構成を変えたい
- 通販・配信・募集などの受付状況をLPに反映したい
- デプロイが失敗した、Netlifyの枠がいつ戻るか知りたい

## When NOT to use
- 会場変更に伴う差し替え一式 → kouen-kaijo-henko
- SNSの告知文 → sns-post-generator（Xは下書きのみ）

## 恒久ルール（ユーザー指定）
- **公開はユーザーの「公開OK」を受けてから。** 準備・確認までは先に進めてよい。
- X の投稿・予約はしない（告知文は下書きだけ）。
- Netlify のトークン類をファイルに書かない。

## Workflow
1. **手元のソースを確かめる。** 前回の作業ディレクトリが残っていなければ、本番から丸ごと復元する：
   ```bash
   python3 scripts/mirror_site.py https://<サイト>.netlify.app/ <作業ディレクトリ>
   ```
   デプロイはディレクトリ全体の差し替えなので、**index.html だけで出すと画像などが本番から消える。** NGに出るのは本番でも404のもの（無くて正常なこともある）。
2. **編集前にバックアップ**（index.before-xxx.html）を取る。
3. **編集はスクリプトで、置換前の文字列が1回だけ出てくることを assert してから置き換える。** セクションの並べ替えは、`<!-- ===== X ===== -->` の目印で行範囲を切り出し、付随する `<style>`・`<script>` ごと動かす。
4. **締切のあるボタン・カードは日付で自動に閉じる**：`data-close="2026-11-30T23:59:59+09:00"` を付け、JSで期限後に「受付終了」に切り替える。締切のたびに再デプロイしなくて済む。
5. **表示確認**：作業ディレクトリを `python3 -m http.server` で配信し、Playwright で 1366px と 375px を撮る。次を確認する：
   - `document.documentElement.scrollWidth` が画面幅と同じ（横スクロールが出ない）
   - pageerror が0件
   - 下部の固定ボタンが375pxで潰れない（ボタン3つ＋LINEまで）

   撮った画像をユーザーに送り、変更点・メリット・リスクを添えて「公開OK」を待つ。
6. **デプロイ**：Netlify MCP の `deploy-site`（siteId 指定）を呼ぶと `npx -y @netlify/mcp@latest --site-id … --proxy-path …` のコマンドが返る。**作業ディレクトリの中で**実行する。proxy-path は短時間で失効するので、毎回取り直す。実行すると作業ディレクトリに `.netlify/state.json` ができる（リポジトリに入れない）。
7. **本番確認**：
   ```bash
   bash scripts/verify_live.sh https://<サイト>.netlify.app "<新しい文言>" "<消えたはずの文言>" assets/main-visual.jpg
   ```
   OKが並んでから「公開しました」と報告する。

## 公演後の組み替えの型（実際に行ったもの）
- トップ直下に「受付中のお知らせ」の3枚カード（例：配信／写真・グッズ通販／出演者募集）。各カードに締切と、該当セクションへのリンク。期限を過ぎると自動で薄くなり「受付終了」になる。
- 並び順：受付中のもの → 作品紹介（あらすじ・キャスト・ギャラリー・スタッフ） → 終わった公演日程は最後。
- ヒーローのボタン、上部メニュー、下部の固定ボタンも同じ優先順に合わせる。
- リスクとして伝える：作品紹介が下がるので、初めて来た人には内容が伝わりにくくなる。
- すべての受付が終わる日を伝え、その後にアーカイブ向けへ直すことを提案する。

## Decision rules
- 手元にソースが無い／古いかもしれない → 本番から復元してから編集する（手元の古い版で上書きしない）。
- 「公開OK」の前 → デプロイしない。以前もらったOKは、そのとき見せた変更にだけ有効。新しい変更には改めてOKをもらう。
- デプロイが credit usage exceeded で止まった → 本番が前の版のままか確認し、下の手順でユーザーに伝える。待つ間は、フォームのURLをX・LINEの告知（下書き）で直接案内する案を出す。

## Netlifyの利用枠切れ
- 症状：デプロイが「Skipped due to account credit usage exceeded」で止まり、本番は前の版のまま。
- 確認：`netlify-team-services-reader` の get-teams で、プラン（type_name）とチーム作成日（created_at）を見る。Freeプランの枠は請求サイクルの頭で戻り、サイクルはチーム作成日の日付に合わせて回る。実際に作成日と同じ日付（19日）にデプロイできた。
- 正確な日付は管理画面（チーム → Usage / Billing）にある、と添える。
- 枠が戻っても「超過」の状態が残り、デプロイできない不具合がコミュニティで報告されている。そのときはサポートへの問い合わせを勧める。

## Quality checks
- [ ] 作業ディレクトリに、本番と同じファイルがそろっているか（復元した場合はNGの中身を見たか）
- [ ] 置換はすべて1回ずつ当たったか（assert）
- [ ] 1366px／375pxで、横スクロールなし・JSエラーなし
- [ ] 「公開OK」をもらったか
- [ ] verify_live.sh がすべてOKか

## Failure modes と Recovery（実際に起きたもの）

| 起きたこと | 対処 |
|---|---|
| コンテナが替わり、編集したLPと画像が消えた | mirror_site.py で本番から復元した（87ファイル） |
| デプロイが利用枠切れで止まった | 本番が前の版のままか確かめ、枠の戻る目安と選択肢を伝えた。枠が戻った日に同じ手順で公開できた |
