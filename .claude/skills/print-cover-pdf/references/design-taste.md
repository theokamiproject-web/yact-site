# デザインの進め方と、依頼者の好みの観測例（依頼者ごとに確認。固定の恒久ルールではない）
## 前例から分かった失敗の構造（台本表紙：6ラウンド×3案で収束せずクローズ）
1. **好きな例が無いまま着手**し、手がかりが「ダサい」「具体的すぎ」など否定の言葉だけだった。
2. **段階が無かった**: 毎回、コンセプト・構図・描き方を仕上げ品質で一度に出したので、指摘の対象が毎回移った。
3. **却下の言葉をそのまま制約にした**: 制約が引き算で積み上がり「線だけ」→終了まで痩せた。自分の仮説（なぜ作品に合うか）と提出前の講評が無かった。
4. **骨格が毎回同じ**（左に図・右に題字・左下ロゴ）でモチーフだけ替えた。題字は18案すべて同じ扱い。線はコードの完璧な幾何形で表情が無かった。

## 進め方（段階ごとに「決めること」は1つだけ）
0. **ブリーフ**（`brief-template.md`）: 好き3〜5点・嫌い2点＋理由、3軸の現在地。埋まるまで描かない。
1. **方向性**（決める: 骨格）: `scripts/skeletons.mjs` を出発点に、**骨格の違う3案**（文字だけ／図が主役／題字を崩す）をラフ品質で出す。モチーフ違いの3案は出さない。
2. **構図**（決める: 配置と大きさ）: 選ばれた骨格の中で、大小・位置・余白の振り幅を2〜3案。
3. **仕上げ**（決める: 線質・書体の細部）: 書体3種（`typography-moves.md`）、必要なら `scripts/roughen.py` で手の痕跡。
- 却下されたら、言葉を制約に足す前に**仮説を1行で立て直す**（例:「静かすぎ」→ 大小差が足りない、と読む）。好みマップに記録して、選ばれた位置の近くで振る。

## 提出前の講評ゲート（毎回・全案）
`scripts/review_sheet.py` で縮小（幅30mm）・ぼかし・反転と数値を1枚にし、**自分で読んでから**出す。
- 縮小で主役と脇役の差が分かるか／題字が読めるか。分からない案は捨てて作り直す。
- 骨格の類似度 0.85 以上の組がある → モチーフ違いになっている。骨格を変える。
- 説明（説明.md）を読まないと伝わらない着想に頼っていないか。
- 捨てた案の数と理由を報告に1行で書く。
- AIの講評は人の評価と一致しないことがある。評価結果（例: 人間評価の実験）が出たら、どの数値が人の評価と合うかで基準を校正する。

## 手の痕跡
採用されたデザインは、線の揺らぎ・途切れ・太さのムラがある側だった。図形レイヤーを `roughen.py`（`--wobble 0.3〜0.6` `--dry 0〜0.15`）に通す。
文字は通さない（可読性）。やりすぎると汚く見えるので、原寸と縮小の両方で確認。SVGフィルタはPDFでラスター化されるので使わない。

## 観測された傾向の一例
- 「寄せ集め」「ダサい」を嫌う。**少ない大きな要素・強い対比・シンプル**を好む。
- 具体物の写実より、図形・線による**抽象**。ただし主題の気配は構造（配置・比率）で示す。
- 短い返答で方向を示す。説明は簡潔、リスクとメリット、数字（余白mm・黒面積%）を添える。
- 素材が届いていない場合、仮置きして進めてよいが、**毎回の報告で未受領と明記**。
