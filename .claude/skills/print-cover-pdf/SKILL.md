# print-cover-pdf

## Purpose
仕様が厳しい（判型・余白・K単色・曲線化・黒ベタ不可）モノクロ印刷物のデザイン案を、**仕様を機械的に満たした入稿用PDF**＋プレビュー＋意図説明として一度で納品する。デザイン案の出し方（収束の速さ）も含む。

## When to use / NOT
- 使う: 表紙・チラシ・ポスター等の「文字＋図形」を、SVGからベクターPDFで作る依頼。判型・余白・色数の指定がある入稿物。
- 使わない: 写真を使うもの／カラー・特色／Word・PowerPoint納品／複数ページ本文組版（→ `pdf` / `docx` 系Skill）／Tシャツの入稿（→ `tshirt-order-handoff`。Tシャツのデザイン生成用Skillはこのリポジトリには無い）。

## Inputs（無ければ最初に1回だけ確認。決められるものは既定で進める）
判型(mm)・塗り足し有無・安全余白・色(K単色か)・載せてよい文言（**これ以外の文字を作らない**）・ロゴ等の素材ファイル・書体条件（商用可）・縮小転用の有無（B5→A6 等）。

## Workflow
1. **仕様を表にする**（`references/spec-checklist.md`）。縮小転用は縦横比が同じか確認（B5とA6は同比率）。
2. **素材の有無を確認**。指定ロゴが無い → 手元の類似素材を**仮置き**として使い、最終報告で「未受領・仮」と明記（黙って代用しない）。ラスター混在のロゴは `references/raster-to-vector.md`。
3. **ブリーフ→段階制作**（`references/design-taste.md`）。着手前に `references/brief-template.md`（好き3〜5点・嫌い2点＋理由、3軸）を埋める。段階は ①方向性＝**骨格の違う3案**をラフで（`scripts/skeletons.mjs`：文字だけ／図が主役／題字を崩す。モチーフ違いの3案は出さない）②構図 ③仕上げ。各段階で決めることは1つ。題字は書体3種以上・大きさは両極（`references/typography-moves.md`）。
4. **SVGを書く**: `scripts/skeletons.mjs` か `example.mjs` を複製。`scripts/lib.mjs` の `vtext/htext`（曲線化。`{family, track}` で書体・字間）・`halo`（白フチ）・`embed`（ロゴ埋め込み）を使う。座標は mm。図形に手の痕跡を足すときは `scripts/roughen.py`（ラスタで崩してベクターに戻す。文字には使わない）。
5. **PDF化**: `svg2pdf.cjs` → `gray_pdf.py`（RGB→K、判型を正確に）→ `check_pdf.py`（寸法・フォント0・画像0・余白実測・黒面積）。
6. **提出前の講評ゲート**: PNG化 → `scripts/review_sheet.py`（縮小30mm・ぼかし・反転・黒面積・要素数・主役占有・骨格の類似度）を**自分の目で読む**。主役が分からない案・題字が読めない案・骨格が似た案（類似度0.85以上で終了コード1）は捨てて作り直す。見切れ・重なりもここで確認。
7. **納品**: PDF／一覧画像／説明md（意図2〜3行・書体とライセンス・未確認事項・捨てた案の数と理由）。好みマップ（`brief-template.md` §4）に1行追記。

## Decision rules
- 余白実測 < 仕様 → 図形を縮める／位置をずらす（端に接する図は**必ず内側へ**。塗り足しなしでは切れ目が出る）。
- 黒面積 > 10〜15% → 面を線・網点へ。「ベタ塗り禁止」でも太い線・文字は可。
- 面を斜線/網点で表現 → 縮小転用で消える。最小線幅・最小網点を説明に書く。
- 画像が1つでも残る(`check_pdf` 画像>0) → SVG内の mask/image 参照を除去（ラスターのマスク残りが原因のことが多い）。
- 非グレー色の警告 → ロゴ内の色味付き黒を `fill` 正規化（輝度から #rrggbb のグレーへ）。

## Quality checks（全てOKで納品）
`check_pdf.py` の全項目OK／`review_sheet.py` を読んで通過／文言が依頼の字句のみ／書体の商用ライセンス記載／仮置き素材・未確認事項の明記。

## Failure modes → Recovery
- 文字が欠ける（書体に無い文字）→ `lib.mjs` が例外を出す。別書体 or 異体字に。
- 図を大きくしすぎ画面端で切れる → 余白実測で検出→縮小。
- 「ダサい」「具体的すぎ」「数が多い」→ `references/design-taste.md`。言葉をそのまま制約に足さず、仮説を1行で立て直す（例:「ダサい」→ 題字が定型・大小差不足・線に表情がない、のどれか）。参考画像が無いまま3ラウンド目に入らない（ブリーフに戻る）。
- 自動の細線太らせ（ロゴ等）で潰れる → 無理に自動化せず、選択肢（作り直し/用途別方式/現状で入稿）を提示。
