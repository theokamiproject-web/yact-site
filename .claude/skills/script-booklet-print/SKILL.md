# Script booklet → 小ロット印刷入稿

## Purpose
台本テキストを、公演会場販売などの少部数(〜100部)向け縦組み冊子の入稿データ(連結PDF＋単ページ版zip)にする。作者の文言は守り、承認された修正だけを反映する。

## When to use / NOT
- 使う: 台本単体の冊子化、その校正、印刷所入稿用PDFの作成、入稿後の誤記訂正と差し替え。
- 使わない: 複数記事の雑誌・ZINE(→ `publishing-studio` 工程)、入稿前の汎用チェックだけ(→ `publication-preflight`)。

## Inputs（無ければ最初に1回だけ聞く。分かるものは聞かない）
台本ファイル、判型(B5/A5/A6/B6)、部数、印刷所、綴じ方向(日本語縦組み=右綴じ)、色(モノ/カラー)、奥付・定価の要否、末尾に入れる文言(例:上演問合せ先)、表紙の方針(写真なし/ロゴ)、期限。

## Workflow
1. **台本の構造を確認**: `templates/build-script-booklet.py` を案件用にコピーして使う(ファイル名・CORR・キャスト表の書式は案件ごとに調整。構造=キャスト/風景/本文、役名行 `役名　台詞`、継続行、ト書き)。本文は2段組(`COLS=2`)の縦組み。
2. **ページ数の見積り**: 判型×文字サイズ×段数で本文ページを出し、**表紙4Pを足した数**が印刷所の許容(例: 24〜340P・2P刻み)に入るか確認。端数は白ページで調整(`ENDBLANK`)。
3. **校正(次の「校正ルール」)**。
4. **組版→入稿PDF**: `scripts/make-print-pdf.sh` で グレー化＋アウトライン＋ページ数検査＋単ページ分割。表紙は別HTMLで作り(塗り足し3mm)、ロゴはベクターを `tools/embed-logos.mjs` で埋め込む。
5. **並べて結合**: 表1, 表2, 本文…, 表3, 表4 の順で `pdfunite`。`scripts/set-trimbox.mjs` で TrimBox(塗り足し3mm内側)を設定。単ページは `pdfseparate` 後に再度 TrimBox を設定(分割で失われる)。ファイル名は `01.pdf`〜(ページ番号=注文ページ数と同数)。
6. **検査**: `scripts/check-print.sh`。さらに全ページを縮小して並べ(montage)、目で見る。
7. **報告**: 注文画面に入れるページ数(表紙込み)、判型、綴じ、色、部数を明記。

## 校正ルール（今回の学び）
- **文言は作者のもの**。誤記が疑われても、ユーザー承認なしに本文を変えない。承認済みの修正だけを `CORR` リスト(`(旧,新)`)に追加して再ビルドする。
- 先に**機械照合**: 組版PDFの文字集合と原稿(CORR適用後)の文字集合を差分(欠落/余分0を確認。ノンブル等の付加分は除く)。アウトライン済みPDFは `pdftotext` で読めない→アウトライン前のPDF/HTMLで確認。
- 読み校正は**4分割して並列**(サブエージェント)し、確実/要確認/表記ゆれに分類させ、**行番号は原稿通し番号に統一**させる(分割ファイルの行番号と混同しやすい)。報告は鵜呑みにせず、該当行を原稿で必ず抜き取り確認する。
- 検証はユーザーと**項目ごとに順番に**: 前後の文脈を示し、「原文のまま/直す」の推奨と理由・リスクを出す。口語台本の言いよどみ・助詞省略・同一人物の別名は意図であることが多い(今回の指摘の大半が意図的と判明)。
- 表記ゆれは**件数を数えて**提示。少数派が数か所のものだけ統一候補にし、口調に関わる(下さい/ください、事/こと、わかる/分かる等)は原則触らない。
- 体裁(半角括弧→全角、全角数字、アポストロフィ曲線/直線、行末空白)は**印刷で見える差**かで判断。組版が自動処理するもの(行末空白、行頭の字下げ等)は対応不要と整理する。

## 組版の判断(if → then)
- 役名ラベルが4字超 → 縮小して小さな2列表示。括弧付き長ラベル(`役名（ト書き）`) → ト書きを台詞の頭へ移す。長ラベルをそのまま流すと数列に折れる。
- キャスト表: 役名欄は最長役名が詰まらない幅に広げる(縮小はユーザーに不評)。**俳優名は縦の同じ高さに揃える**。1行に収めたい行は `white-space:nowrap`＋固定幅。
- `.cast` の `text-indent:-Nem` は子の inline-block に継承される → 固定幅の子には `text-indent:0` を付ける(付けないと文字が重なる)。
- 後勝ちCSS: 名前付きページ(`@page door`)は `@page :nth(N)` より優先される。ページ固有のマージンボックス(末尾の連絡先など)は専用の名前付きページを作り、同じクラスを定義している**後ろのCSSに上書きされていないか**を確認する。
- 縦中横(tcy)の正規表現は、HTMLタグと実体参照(`&#x27;`)を飛ばす。飛ばさないと `Let&#x27;s` のように文字化けする。
- 右綴じでは偶数ページが右ページ(ノド=左端)。最終ページ左下の文言はノド側で隠れるリスクをユーザーに伝える。
- 「終」などの位置は、段組の上段の最下端に合わせる指定があればそれに従う。

## 入稿前チェック(必須)
全ページ同一サイズ(判型+塗り足し) / TrimBox設定 / フォント0(アウトライン) / カラーCMY混入0(モノの場合) / 白ページ(表2・3・4等)が白データとして存在 / ページ数=注文ページ数(表紙込み) / 単ページ版のファイル数一致 / 全ページ縮小目視。

## Failure modes → Recovery
- ビルドが失敗しても `&&`/`set -e` の連鎖次第で古い成果物が使われる → `make-print-pdf.sh` のページ数検査と、ビルダー単体実行でエラー確認。
- 「修正を入れたのにPDFに出ていない」: CORRの置換文字列が実際の原文と一致していない(スペース有無)。HTMLで新旧文字列を `grep -c` して確認してから送る。**検証前にファイルを送らない**(誤版を送った場合は即訂正して最新版を明示)。
- 送信前に出力を見ていないページが無いか(今回、末尾の連絡先が白紙のまま出力されていた)。末尾ページは必ず画像確認。
- 入稿後に誤記発見: 入稿状況(未入稿/製造前/製造後)を聞く → 製造前なら修正版を作って差し替え依頼文(注文番号・誤→正・差替範囲・支払いは確認後)を下書き。外部への送信はユーザーが行う。旧データは消さず、新フォルダに出力して前版と**画像差分**を取り、差分ページが想定どおりか確認する。
