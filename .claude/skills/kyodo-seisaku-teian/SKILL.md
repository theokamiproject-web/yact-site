# 共同制作提案書のブラッシュアップ

提案先（劇団・劇場）に送る「本体」と「別紙」を、矛盾なく、控えめな体裁のPDFに仕上げる。

## 使わない場面

- 学校・福祉・観光課へのWS営業提案 → okami-business-assistant
- 助成金の申請書 → josei-* 系
- A4一枚のチラシ・送付状だけ → pdf-eigyo-maker
- 公演後の報告書、当日パンフ → kouen-pamphlet-maker 等

## 入力

- 提案書の原稿（チャット貼り付け、Doc、Markdown）。別紙があればそれも
- 提案先の名称、送付形態（メール添付PDFか、紙か）、提出日
- 文面の書き手名義（通常は OKAMI企画 代表 真坂 雅。肩書・連絡先は okami-business-assistant 参照）

## 作業の流れ

1. **原本をMarkdownにする**。`proposals/<作品略称>-teian.md`（別紙は `-bessi.md`）。表紙ブロックの書き方は `scripts/md_to_print_html.py` 冒頭の規約に合わせる（`# タグ`、`## タイトル`、`### サブタイトル`、`ラベル：値` 行、`---` で本文開始、最後の `---` 以降が問い合わせ欄）。以後の修正はすべてこのMarkdownに入れる。PDF用HTMLを手で直さない。
2. **最初の診断を出す**（直す前に）。未完成の印（「←」「要検討」等）、日付表記の混線、冗長な重複、分量、リスク（権利・テーマの重さ）、残すべき強み（具体的な数字）を5項目前後で。ユーザーの返事が「それで」「よろしく」なら、そのまま全部反映してよい。
3. **反映する**。判断の基準は下の「判断ルール」。
4. **突合する**（送付物を作るたび必ず）: `python3 scripts/crosscheck.py 本体.md 別紙.md`。指摘は全件ユーザーに報告し、直す/残すを分ける。
5. **PDFにする**: `bash scripts/build_pdf.sh 本体.md 出力.pdf 作業ディレクトリ`。別紙も同様。出力のPNGを1回だけ見て、崩れがなければ PNG を消す。
6. **納品**: PDFを送付（SendUserFile）、Markdownと PDF をコミット。Web表示版（Artifact）は頼まれたときだけ作る。

## 判断ルール

- 未完成箇所の穴埋めは、案を1つ書いて「これでよいか」を聞く。創作判断（結末・トーン）は複数案を比較して止まる（`references/story-options.md`）。整合性の修正（設計表と本文のずれ等）は聞かずに直し、何を直したかを報告する。
- クレジットの出演・主催は**提案先を先に**書く（例: 「提案先の俳優陣、客演、当方」の順）。
- **初回提案では具体的な金額を出さない**。本体に金額がないのに別紙に「制作費○万円」があれば抽象化する（`references/rights-appendix.md`）。
- 設計表に「踊り：序盤・中盤・終盤」のような**回数や配置を書いたら、あらすじと協働の章に同じ回数分の描写があるか**を確認する。足りなければ小さな伏線（口ずさむ等）を1文ずつ足し、協働の章に構成の説明を1文入れる。
- 分量を減らすときは、挨拶・演出意図・提案先への想いの章を先に圧縮する。表や設計表に既にある数字（上演時間等）は本文で繰り返さない。人物表・設計表・結びは削らない。
- 体裁は**きらびやかにしない**。アニメーション、グラデーションの見出し帯、飾り記号は使わない。朱の枠タグ＋見出しの細線＋表、で足りる。
- 別紙をPDFで同封するなら、本体の「参考資料」（リンク）欄は削る。
- 提出日は送付日に合わせる。「京にして」のような同音の誤変換（今日）は文脈で読み替え、何日にしたかを書いて報告する。
- ユーザー提供の法務文面は語句を変えない（構造化だけ）。

## 完了前チェック

- [ ] `crosscheck.py` の指摘ゼロ、または残す理由をユーザーに伝えた
- [ ] 本体・別紙・Web版がある場合、全部に同じ修正が入っている（Markdownから生成していれば自動で揃う）
- [ ] クレジット順（提案先が先）、提出日、宛名（「○○ 御中」）
- [ ] 金額・章参照・URLの残り
- [ ] 組版チェック通過、ページ数、PNGで字形（明朝が中国語字形・ゴシックに化けていないか）
- [ ] 確認用PNGを削除した

## 失敗例と直し方

| 起きたこと | 直し方 |
|---|---|
| 本体・Web版・印刷用HTMLを手で別々に直し、印刷版の表から文言が抜けた | Markdownを原本にし、印刷HTMLは毎回 `md_to_print_html.py` で生成する |
| 別紙作成時に本体と突合せず、本体にない金額と章参照（「第4章の外販」）が残った | 別紙を作ったら即 `crosscheck.py`。ユーザーに聞かれる前にやる |
| Web版のヒーロー（雪のアニメ・夜色グラデ）が読みにくく、「きらびやか」と指摘された | 提案書は書類。装飾は削り、印刷版と同じ控えめな体裁にする |
| 背景色をテーマ変数に依存させ、ライト表示で見出し文字が背景に溶けた | 文字を載せる帯は固定色にするか、そもそも帯を使わない |
| 結末の方向性を勝手に一案に決めかけた | 創作判断は比較表＋推奨で止め、ユーザーの選択を待つ |
| `pip install` 後も weasyprint が無い／Pillow の ImportError／フォント未導入 | `build_pdf.sh` が対処済み（`python3 -m pip`、`--ignore-installed pillow`、`apt-get update`→`fc-cache`）。それでも駄目なら手で実行してエラーを見る |
| 組版チェックが「不要スペース」を誤検知 | `<p>` 内の全角スペース区切りが原因。「・」に替える |

## ファイル

- `scripts/md_to_print_html.py` — Markdown → 印刷HTML（表紙・クレジット表・表・番号リスト・問い合わせ欄）
- `scripts/build_pdf.sh` — 環境準備 → HTML → PDF → 組版チェック → ページ数 → 確認PNG
- `scripts/crosscheck.py` — 未完成の印・金額・章参照・URL・版ずれの突合
- `templates/print.css` — OKAMI企画の色と書体（朱・金・墨・和紙、Noto Serif/Sans CJK JP）
- `references/story-options.md` — あらすじ方向性の観客層別比較と、明るくする書き換え
- `references/rights-appendix.md` — 権利・著作権の別紙の扱いと突合項目
